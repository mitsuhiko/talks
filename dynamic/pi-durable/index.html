The one rule

Nothing is shown before it is stored

One line of atomic commitsTranscript entries, tasks, and state change together, or not at all.

Streaming is committed tooTokens and tool output land in storage at most every 100 ms.

So recovery is reopeningA crash loses at most 100 ms. The screen is a window onto storage, not onto the process.

Durability

Tools say whether they are safe to rerun

const searchIssues = defineTool({
  name: "search_issues",
  description: "Search the issue tracker",
  parameters: Type.Object({ query: Type.String() }),
  replay: "safe", // only reads: rerun after a crash
  execute: async (args, api) => {
    api.output(`searching for ${args.query}\n`);
    const text = await tracker.search(args.query);
    return { output: [{ type: "text", text }] };
  },
});

const deploy = defineTool({
  name: "deploy",
  description: "Deploy a version to production",
  parameters: Type.Object({ version: Type.String() }),
  // no replay: interrupted means the model is told
  execute: async (args) => {
    const text = await ci.deploy(args.version);
    return { output: [{ type: "text", text }] };
  },
});

Scheduling

Your own work is a durable task too

type State = { phase: "wait" } | { phase: "deliver" };
const Reminder = defineTask<{ text: string; at: number }, State, null>({
  name: "app.reminder",
  version: 1,
  initial: () => ({ phase: "wait" }),
  phases: {
    wait: async (task, runtime, ctx) => {
      await runtime.sleep(task.input.at, ctx); // wall-clock deadline
      await runtime.commit(() => ({
        status: "running", checkpoint: { phase: "deliver" } }), ctx);
    },
    deliver: async (task, runtime, ctx) => {
      const chat = await runtime.conversation(task.conversationId, ctx);
      await chat!.submit({ type: "input", content: task.input.text,
        requestId: `reminder:${task.id}` }, ctx);
      await runtime.commit(() => ({ status: "terminal",
        outcome: { status: "completed", result: null } }), ctx);
    },
  },
  abort: (_task, runtime, ctx) => runtime.commit(() => ({
    status: "terminal", outcome: { status: "aborted" } }), ctx),
});

Mon 18:02“Remind me tomorrow at 9.” A tool creates the task.

Mon 18:02wait sleeping until Tue 09:00

Mon 23:40Redeployed. The task is still waiting.

Tue 03:12The laptop slept. Still waiting.

Tue 09:00deliver: the reminder arrives in the conversation, once.

Model requests, tool calls and compaction are tasks like this one, in one ownership tree: Esc aborts what a task owns, bottom-up.
